# IPzZPort

IPzZPort 在指定地址和端口接收 TCP 连接，再把数据转给固定后端。入口和后端可以分别使用 IPv4 或 IPv6，端口也可以不同。适用于 HTTP、HTTPS 或其他 TCP 服务。需要 Python 3.11 或更新版本，转发核心和 Web 面板仅依赖标准库；桌面控制窗口额外需要 PyQt5。

## 双击启动（Linux）

双击项目目录中的 **IPzZPort.desktop**，打开独立的桌面服务控制台。窗口提供「启动」「停止」「重启」「打开 Web 面板」「刷新状态」，每 2 秒更新运行状态、PID、规则数、监听数和活动连接，同时显示最近的运行日志。控制台在服务停止时仍可使用，打开窗口本身不会自动启动服务。

关闭控制窗口或浏览器不会停止后台转发。停止服务会断开全部转发连接；重启会恢复之前保存为启用的规则。启动器只停止自己启动的进程，其他方式启动的服务会显示为「外部启动」。如果文件管理器提示不可信，选择「允许启动」或在文件属性中允许执行。

桌面控制台可在服务停止后修改「Web 端口」，点击「应用端口」再启动；运行中会禁用修改。端口和桌面主题保存到 `.runtime/preferences.json`，下次双击自动恢复。端口被其他程序占用时也可以另选端口。日志按端口保存，例如 `.runtime/panel-8765.log`。

桌面右上角和 Web 页头均提供「紫色系 / 深色系 / 浅色系」，默认紫色，即时切换且不影响转发。两端分别保存主题；Web 使用浏览器本地存储，因此换端口或浏览器会使用该来源自己的选择。

桌面窗口使用 PyQt5（当前机器已安装），按钮、输入框和状态卡片使用圆角样式。自动查询状态时保持按钮可用，只更新发生变化的内容；查看历史日志时保留滚动位置。也可使用命令行：`python3 launch.py --start`、`--stop`、`--restart`、`--status`；`--status` 输出 JSON。这些命令默认使用已保存端口，可用 `--port 9876` 显式覆盖。直接运行 `ipzzport.py --web` 则继续使用默认 8765 或显式 `--web-port`。

启动图标使用当前项目的绝对路径，移动目录后需相应更新 `IPzZPort.desktop` 的路径，也可直接运行 `python3 launch.py`。

## Web 管理面板

```bash
python3 ipzzport.py --web
```

打开 [本机管理面板](http://127.0.0.1:8765/)。页面可新增、编辑、启停和删除规则，刷新后可查看活动连接数。规则保存到项目目录的 `panel-state.json`，启用的规则会在重启面板时恢复。可用 `--web-port` 更换端口，或用 `--web-state` 指定独立规则文件。命令行的 `--config` 模式继续使用自己的 TOML 文件。

### 用 OneNav 测试 IPv4 和 IPv6 同端口访问

1. 在 OneNav 的运行终端停止旧实例，进入 OneNav 目录后执行 `ONE_NAV_HOST=0.0.0.0 ./start.sh`。可用 `ss -lntp 'sport = :9632'` 确认 OneNav 只监听 `0.0.0.0:9632`。
2. 打开 IPzZPort 面板，点击「填入 OneNav 示例」，保存 `[::]:9632` → `127.0.0.1:9632` 规则。此示例监听所有本机 IPv6 地址，包括公网地址。
3. 打开 `http://127.0.0.1:9632/` 和 `http://[::1]:9632/`。IPv4 入口直达 OneNav，IPv6 入口由 IPzZPort 转发。
4. 确认路由器和本机允许 IPv6 TCP `9632` 入站，再从具备 IPv6 的外部网络访问 `http://[公网IPv6]:9632/`。面板仍使用本机地址管理。如果只需本机测试，可改为 `[::1]:9632`；`[::1]` 不能接收外网连接。

## 单条转发

下面的命令仅供本机测试，把 IPv6 回环地址的 `19632` 转到 IPv4 服务 `9632`。如需外网 IPv6 入口，将 `--listen` 改为 `'[::]:19632'`。

```bash
python3 ipzzport.py --listen '[::1]:19632' --target '127.0.0.1:9632'
```

如果后端是 HTTP，可访问 `http://[::1]:19632/`。反向转发的写法如下，假设后端服务监听 `[::1]:9633`。

```bash
python3 ipzzport.py --listen '127.0.0.1:19633' --target '[::1]:9633'
```

程序在前台运行，按 `Ctrl+C` 停止。地址必须使用 IP 字面量，IPv6 地址加方括号。

## 让 IPv6 外网访问 IPv4 服务

假设现有服务监听 `0.0.0.0:8080` 或 `127.0.0.1:8080`，以下命令接收 TCP `8080` 的 IPv6 连接，并转给原服务。

```bash
python3 ipzzport.py --listen '[::]:8080' --target '127.0.0.1:8080'
```

`[::]` 绑定所有本机 IPv6 地址，包括公网地址。IPv6 套接字启用 `IPV6_V6ONLY`，因此可以和 IPv4 的 `8080` 监听同时运行。如果该服务已经双栈监听同一个端口（例如之前用 `[::]:9632` 启动的 OneNav），可选择另一入口端口。若要限制入口，可将 `[::]` 换成指定的本机 IPv6 地址。

通过 DDNS 访问时，将域名的 `AAAA` 记录指向这台机器的公网 IPv6，并确保路由器和本机防火墙允许入口 TCP 端口。IPv4 客户端要访问 IPv4 入口，也需要可用的 IPv4 路由。IPzZPort 原样传输 TCP 数据，HTTPS 和认证由后端负责，后端看到的连接来源是 IPzZPort。

## 多条规则

复制示例并按各服务填写监听地址和目标地址。

```bash
cp config.example.toml config.toml
python3 ipzzport.py --config config.toml --check
python3 ipzzport.py --config config.toml
```

```toml
connect_timeout = 5.0

[[rules]]
listen = "[::1]:19632"
target = "127.0.0.1:9632"

[[rules]]
listen = "127.0.0.1:19633"
target = "[::1]:9633"
```

`--check` 校验配置。正常启动时会尝试绑定所有入口，任一入口绑定失败时会提示地址并退出。`connect_timeout` 是连接后端的超时时间，单位为秒，可用 `--connect-timeout` 覆盖。每条规则应指向真实后端，避免把一组规则首尾相接形成循环。

## 排查

- **无法监听**：用 `ss -lntp` 查看端口是否已被占用，并确认指定的监听 IP 已分配给本机。
- **连接后端失败**：在转发机器上直接连目标地址，检查服务监听的地址族和端口。
- **本机访问正常、外网超时**：检查监听地址、客户端 IPv6 连通性以及路由器和本机防火墙的入站规则。

当前版本支持 TCP。运行测试可用 `python3 -m unittest -v`。
